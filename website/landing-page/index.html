LLMs don't know when they're wrong.
Pinocchio does.

Estimate the uncertainty of any LLM response in a single forward pass. No access to model internals needed. Just pip install and go.

Why Pinocchio?

A lightweight uncertainty judge that works with any language model.

🌐

Any Model

Works with GPT-5, Claude, Gemini, LLaMA, Qwen — anything that produces text. No model access needed.

⚡

Single Pass

One forward pass through a tiny 0.8B model. No sampling, no multiple generations, no chain-of-thought.

🎯

Calibrated

Returns real probabilities P(correct) ∈ [0, 1], not just yes/no. AUROC 0.878 across 20+ benchmarks.

📦

Tiny & Fast

0.8B parameters. Runs on CPU (~2 GB RAM). No GPU required. ~25 MB LoRA download.

🔄

Cross-Model

Trained on GPT-5, Qwen, and others. Generalizes to unseen models without retraining.

🖼

Multimodal

Handles both text LLM and vision-language model (VLM) outputs. One model for everything.

Quickstart

Three lines of code to score any LLM response.

from openai import OpenAI from pinocchio import Pinocchio client = OpenAI() judge = Pinocchio() # downloads weights automatically (~25 MB) messages = [{"role": "user", "content": "What is the capital of France?"}] response = client.chat.completions.create(model="gpt-5", messages=messages) score = judge.score(response, messages=messages) print(f"P(correct) = {score:.3f}") # P(correct) = 0.97

Works with any provider — just pass the question and answer.

# Score a Claude response score = judge.score( question="Explain quantum entanglement", answer=claude_response_text, source_model="claude-4-sonnet", ) # Selective prediction: abstain when uncertain if score >= 0.7: print(response) else: print("I'm not confident. Let me escalate.") # Batch scoring scores = judge.score_batch([ {"question": "What is 2+2?", "answer": "4"}, {"question": "What is 2+2?", "answer": "5"}, ])

How It Works

Pinocchio scores responses in three simple steps.

Ask Any LLM

Send your question to GPT-5, Claude, Gemini, or any model via their normal API.

Pass to Pinocchio

Give Pinocchio the question and the LLM's answer. It doesn't need model weights or logits.

Get P(correct)

Pinocchio returns a calibrated probability. Use it for routing, filtering, or flagging.

Pinocchio vs. Alternatives

✅ Pinocchio

  • ✔ Works on closed-source models (GPT-5, Claude)
  • ✔ Single forward pass (no sampling)
  • ✔ 0.8B parameters, runs on CPU
  • ✔ Cross-model transfer (train on A, eval on B)
  • ✔ Handles text + vision
  • ✔ Calibrated probabilities
  • ✔ Open weights (Apache 2.0)

Other Approaches

  • ✘ Logit-based: Requires model internals
  • ✘ Semantic Entropy: Needs N generations ($$$)
  • ✘ Self-Consistency: Needs N generations ($$$)
  • ✘ Verbalized confidence: Poor calibration (0.61 AUROC)
  • ✘ MC Dropout: Requires open weights + dropout
  • ✘ Ensemble methods: Need multiple models

Use Cases

Practical applications for uncertainty-aware LLM systems.

Production

Selective Prediction

Only serve answers above a confidence threshold. Abstain or escalate to a human when uncertain.

Cost Saving

Smart Model Routing

Start with a cheap model. If Pinocchio flags low confidence, retry with a stronger (more expensive) model.

Safety

Error Detection

Flag likely-wrong answers for human review in high-stakes domains: healthcare, legal, finance.

Evaluation

Benchmark-Free Accuracy

Estimate model accuracy on new data without ground-truth labels. Rank models by predicted correctness.

Research

Active Learning

Identify which examples a model struggles with. Focus annotation effort where it matters most.

UX

Confidence Indicators

Show users a confidence score alongside each response. Build trust through transparency.
